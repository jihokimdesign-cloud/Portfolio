01Context

Growing pains and accessibility debt

Project Sidewalk is an open-source civic platform that crowdsources urban accessibility data to train machine learning models. With 350,000+ accessibility labels from 11,000+ volunteers, it had proven its value. Underneath, the architecture and experience were brittle.

01
User drop-off

Inconsistent UI and unclear feedback caused high abandonment in the core reporting flows.

02
Engineering bottleneck

With no central design system, developers rebuilt components from scratch, piling up technical debt and frontend regressions.

03
The accessibility irony

A tool built for accessibility failed basic WCAG standards, alienating the very community it served.

02Stakeholders

Three groups, one answer

Redesigning a civic platform meant balancing three groups with competing needs. An accessible-by-default design system was the only way to serve all of them at once.

The mappers
Citizens & volunteers
  • Map barriers quickly and accurately
  • Low cognitive load, gamified flows
  • WCAG AA compliant interface
Data consumers
City planners & governments
  • High data accuracy for planning
  • Standardized reporting formats
  • Reliable UI that prevents input errors
Internal team
Engineers & maintainers
  • Scale to 8+ cities without regressions
  • A reusable component library
  • Fewer UI-related GitHub issues
03Research

Data-informed diagnostics

Instead of relying on intuition, I audited the existing experience with quantitative and qualitative data to find the highest-impact fixes.

Behavioral analysis

Hotjar heatmaps and session recordings to find drop-off points, navigation friction and hesitation.

Community voice

GitHub issues and forum discussions, synthesized into prioritized pain points.

WCAG 2.2 AA audit

A heuristic evaluation for contrast, keyboard navigation and screen reader support.

Recreated visualization. Hotjar data is confidential; patterns and proportions reflect real findings.

04System

Accessible by default

My goal shifted from delivering polished screens to building infrastructure. Two decisions made compliance automatic instead of something to fix later.

Decision 01
Tokens as a single source of truth

I defined atomic design tokens and mapped Figma variables 1:1 to the engineers' SCSS variables, removing guesswork at handoff.

Decision 02
Compliance built into components

Every component ships WCAG 2.2 AA compliant. Any future feature built from them inherits accessibility, with no retroactive fixes.

05Adoption

A working contract, not a style guide

A design system is only as good as its adoption. Working closely with 1 PM and 2 developers, I treated it as a working contract between design and engineering, rolled it out in phases with detailed spec handoffs, and championed it across the organization.

Validation chips before and after the system.

07Reflection

Systems thinking in civic tech

A design system isn't just a style guide. It lets inclusivity live in the code, not only the pixels.

01
Designing for resilience

The project moved me from designing for the happy path to designing for resilience in open-source, civic environments.

02
Infrastructure over surface

Treating design as infrastructure let 3 teams ship accessible features without extra effort.

03
Scale needs a system

In civic tech a design system isn't a luxury. When inclusivity is in the architecture, every new feature inherits it.
